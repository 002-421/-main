# XRS-AI-03: аудит и контрольные проверки

## Источник и структура

База: `codex/xrs-ai-review-02` (`a4ae68c1f004c90a863045a4b31bd3bd2be292b8`). PR #8 и #9 оставлены Draft. Модуль работает в существующем XRS; feature flag выключен по умолчанию.

Каталог содержит 55 МРТ и 58 КТ шаблонов. Все 58 КТ проверены после штатной подготовки нового документа. 17 используют `ЗАКЛЮЧЕНИЕ:`, 41 — `ЗАКЛЮЧЕНИЕ.`; у второй группы нет второго визуального разделителя. Все 58 имеют однозначное начало шапки, описания, заключения и подписи после подготовки. Проверенные индексы и вид маркера сохранены в `src/ai-review-boundaries.json`. Разметка выполняется только для нового документа из встроенного шаблона. При расхождении индексов, порядка или контрольных строк создание структурированного документа останавливается. Существующие документы и пользовательские шаблоны остаются без автоматической миграции.

Автоматические проверки для всех 113 шаблонов подтверждают, что четыре секции имеют нужные ID, а развёрнутый список вложенных узлов побайтно равен подготовленному документу. Проверены отсутствие данных шапки и подписи в извлечённых блоках и DOCX round-trip представителей МРТ и КТ.

## Ручная миграция

За выключенным feature flag врач выбирает начало описания, заключения и подписи по абзацам, видит полный локальный предварительный просмотр четырёх блоков и подтверждает границы флажком. Частично структурированные документы отклоняются, повторная миграция уже размеченного документа не применяется.

До изменения редактора исходный JSON текущей вкладки записывается в отдельную запись `localStorage` с UUID и SHA-256. Запись читается обратно, сравнивается с исходными байтами и проверяется хеш. Затем Tiptap получает точное новое состояние, проверяется сохранность всех исходных узлов и результат в рабочем пространстве. При сбое редактор восстанавливается из резервной копии; копия не удаляется. После перезапуска её можно выбрать через кнопку восстановления. Тесты покрывают ошибку записи, отсутствие readback, повреждение, повторное применение и восстановление после сбоя. Резервная копия хранится в профиле браузера/Electron; удаление данных приложения удалит и её. Для защиты от такого сценария нужен отдельный экспорт копии в файл на следующем этапе.

## Предлагаемые исправления

Адаптер применяет отдельную подтверждённую врачом правку в пределах одного абзаца через несколько текстовых узлов с различными marks одной транзакцией ProseMirror. Перед применением он проверяет активную вкладку, полный текст разрешённого блока, исходный диапазон и тип операции. Соседние узлы и форматирование сохраняются; Undo/Redo проверены. Диапазоны через абзацы, таблицы, изображения или изменение структуры абзаца отклоняются для ручного редактирования. Mock-провайдер не выполняет клинический анализ, облачный режим отключён.

## Проверки и границы доказательств

- `npm run build`, `npm test`, штатные браузерные тесты вкладок и восстановления, тесты AI Review и миграции, `npm run test:browser` в Electron, `npm run test:morphology-browser`.
- Визуально сопоставлены PDF до и после структурирования для встроенного шаблона МРТ `head-gm` (3 страницы) и КТ `ct-c8babc4c5b` (2 страницы). Все страницы растеризованы при одинаковом масштабе; число отличающихся пикселей — 0 на каждой странице. Остальные 111 шаблонов визуально не проверялись.
- Испытания проведены на встроенных шаблонах и искусственных протоколах. Реальные пациентские документы и облачная передача не использовались.

Для XRS-AI-04 остаются файловый экспорт резервной копии, проверка PDF остальных шаблонов, сложные правки через границы абзацев и отдельная оценка обезличивания перед любым облачным провайдером.
