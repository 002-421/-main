# XRS-08 — подготовка каналов Stable/Beta

## Аудит исходного updater

- Официальная 0.4.54 читает `https://raw.githubusercontent.com/002-421/-main/codex/mri-report-studio/x-ray-report-studio/downloads/latest.json` и принимает только числовую версию и ZIP `X-ray_Report_Studio_Windows_Setup.zip`.
- Стабильная установка хранит Chromium-профиль в `%APPDATA%\MRI Report Studio`; общий словарь — в `%PUBLIC%\Documents\MRI Report Studio\dictionary.json` либо в профиле пользователя. В Chromium-профиле находятся workspace, черновики, история Undo, пользовательские шаблоны, настройки и печати. Папка установленной версии отделена от профиля.
- Установщик сверяет SHA-256 ZIP с манифестом, проверяет ZIP-пути, распаковывает приложение рядом с предыдущей версией, тестирует запуск, резервирует пользовательские данные и только затем меняет ярлык. Загрузка разрешена с HTTPS-доменов GitHub. Цифровой подписи издателя у архива нет; SHA-256 защищает от повреждения относительно доверенного манифеста, но не от компрометации самого репозитория.
- Прежний код не поддерживал prerelease и отдельный манифест Beta. Программа 0.4.54 не может самостоятельно перейти в Beta: её интерфейс не содержит переключателя.

## Выбранная схема

- Stable продолжает читать прежний `latest.json` и прежний ZIP. Никакие бета-версии в нём не публикуются.
- Beta дополнительно читает `downloads/beta.json`; выбирается наиболее новая подходящая версия из Beta и Stable. Сравнение учитывает, что `0.4.55-beta.1 < 0.4.55`; понижение запрещено. Пока `beta.json` не опубликован, Beta может читать Stable без ошибки.
- Имена и пути манифестов и ZIP фиксированы в приложении. Манифест проверяется на допустимую версию, HTTPS URL в нужной ветке, SHA-256 и размер примечаний. Скачивание ограничено по размеру; обрыв и неверная длина отклоняются.
- Настройка канала хранится локально в `%APPDATA%\X-ray Report Studio Channel.json` и поэтому не влияет на другие компьютеры. Данные Beta находятся в отдельном `%APPDATA%\MRI Report Studio Beta`; её словарь также внутри этого каталога. Никакие протоколы из Stable не копируются в Beta автоматически.
- Включение Beta из новой версии Stable сначала сохраняет открытые черновики и проверяет резервную копию рабочего профиля, затем переключает локальный канал и перезапускает приложение с отдельным профилем. Несохранённые в DOCX/PDF документы блокируют переключение. Выключение Beta не запускает старую Stable на новых данных и не понижает приложение.
- Первая 0.4.55-beta.1 распространяется для ручной проверки как portable ZIP, поскольку установленная 0.4.54 не знает о Beta. Перед первым запуском рядом с EXE находится `Start-XRS-Beta.cmd`: он закрывает путь к запуску, пока проверенная резервная копия Stable не создана. Первое прямое открытие Beta EXE при наличии Stable-профиля блокируется до завершения подготовки. Тестовый комплект не меняет рабочий ярлык 0.4.54.
- CI artifact `X-ray_Report_Studio_Windows_Beta_Setup.zip` содержит полный portable Windows runtime, приложение, `Start-XRS-Beta.cmd` и проверенный backup script. Он подходит для первого ручного запуска; встроенный updater должен получать отдельный app-only пакет, подготовленный под его формат. Candidate manifest содержит только версию и SHA-256, не является манифестом обновлений. `latest.json` не меняется.

## Первый запуск на домашнем Windows 11

1. Скачайте `X-ray_Report_Studio_Windows_Beta_Setup.zip` из успешного CI artifact, распакуйте в отдельную папку вне рабочей установки 0.4.54.
2. Закройте X-ray Report Studio 0.4.54 и откройте `Start-XRS-Beta.cmd` из распакованной папки. Он сохранит проверенную резервную копию Stable-профиля локально в `%APPDATA%\X-ray Report Studio Backups` и запустит Beta. Если резервирование не удалось, Beta не запускается.
3. В настройках убедитесь, что указаны версия `0.4.55-beta.1` и канал Beta. Первоначально профиль Beta пустой. Создавайте в нём только искусственные протоколы до ручной приёмки; рабочие данные Stable остаются в прежнем профиле.
4. Пока `beta.json` не опубликован, команда проверки обновлений не установит новую Beta. После отдельного разрешения публикации Beta будет предлагаться через интерфейс и устанавливаться только после подтверждения пользователя.
5. Для возврата к рабочей 0.4.54 запустите прежний ярлык Stable. Выключение Beta в её настройках меняет канал проверки обновлений, но не удаляет Beta-профиль и не выполняет понижение версии.

## Ограничения перед публикацией

- Работу механизма на реальном Windows 11 и установленной Microsoft Word необходимо проверить вручную. Windows Server 2022 CI не заменяет эту проверку.
- Первый вход в Beta требует отдельного portable комплекта; установленная 0.4.54 не умеет включать Beta сама.
- Данные между Stable и Beta автоматически не синхронизируются. Это защищает рабочие протоколы от новых функций, но требует сознательного переноса отдельных файлов через проверенный импорт.
- Манифест и ZIP Beta пока не опубликованы. Наличие кандидата в CI artifact не активирует канал обновлений.
