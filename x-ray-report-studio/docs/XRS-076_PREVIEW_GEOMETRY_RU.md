# XRS 0.4.76 — геометрия единственного предпросмотра

База: опубликованный тег xrs-v0.4.75, cd04277c41c84e7f0152a33b41ce538d0caefb9d.
Публичный ZIP 0.4.75 проверен: 99eca95165d5edf5c4c6ff977f1f30f7df77cabd92e0d8120cd37da1757534df.

## Подтверждённые расхождения

- CSS видимого контейнера задавал 1.239; измерительный контейнер имел 1.05!important, печать — 1.05!important. Явные интервалы абзацев могли перекрывать наследование, поэтому ошибка зависела от документа. История введения константы: 25b4285, без соответствующего правила 1.239 в DOCX.
- DOCX хранит поля, размер листа и отступы в целых twips. Старый HTML оставлял исходные миллиметры. Например A4 210 mm округляется до 11906 twips; поля по умолчанию 1020 twips, то есть 17.9917 mm. Разница ширины мала; она сама по себе не доказывает причину всех переносов в Word.
- DOCX явно задаёт widowControl; прежнее разделение абзаца по максимальному помещающемуся слову не контролировало число оставшихся визуальных строк.
- На малом экране тест воспроизвёл перехват щелчка скрытой панелью: авторское display:grid перекрывало стандартное hidden. Восстановлена семантика hidden; существующий диалог предпросмотра поднят над всплывающими панелями.

## Исправление

word-preview.ts проецирует уже выбранный экспортный документ и PrintBox в отдельный отсоединённый DOM существующего предпросмотра. Геометрия округляется как в фактическом DOCX. Для абзацев используются размеры, отступы и интервалы источника, включая максимум inline line-height и источник Title/Heading. Минимум строки берётся из w:spacing (atLeast, twips); футер соответствует отступу 369 twips и AUTO 200/240.

Разрывы в экранной проекции учитывают минимум две визуальные строки до/после разрыва. Продолжение абзаца не повторяет отступ первой строки. Калибровка пересчитывает базовую вместимость на этой геометрии; существующий ключ xrs.preview-calibration.v1 и UUID врача, enabled, offset, lastTarget не мигрируются и не сбрасываются.

Экспортный PrintPlan, docx.ts, print-layout.ts, медицинские шаблоны, updater и release workflow не изменяются. Поправка врача по-прежнему не влияет на Word/PDF. Одно окно предпросмотра имеет видимый заголовок/кнопки, прокрутку содержимого и контрастные настройки в двух темах. Семантика редактирования, формат документов и профиль не изменены.

## Проверки

- Реально экспортированный приложением DOCX: сравнение OOXML с DOM в mm (лист, поля, полезная ширина, левый/правый/первый отступ, ширина абзаца); line/spacing в pt.
- Реальные Range.getClientRects: длинные абзацы вокруг разрывов, отсутствие одиночных строк, повторного первого отступа, потерь текста и пересечений с футером/подписью.
- Темы light/dark, окна 1500×1000, 900×600 и 640×480, контраст минимум 4.5:1, фокус и прокрутка, неизменность ранее сохранённой калибровки после перезапуска.
- При непомещающемся из-за калибровки изображении возврат использует новую базовую геометрию, без возврата к старым CSS-размерам.
- Сравнение реально экспортированных document.xml и PDF-входного HTML в исходном bundle 0.4.75 и новом 0.4.76: идентичны для синтетического многостраничного документа со смешанными размерами и отступами.
- Существующие проверки 1–5 страниц, смешанных размеров, таблиц, явного разрыва, заключения, семи размеров шрифта, экспорта, Undo/Redo и восстановления вкладок сохранены.
- Windows CI выполняет новый сценарий внутри существующего xrs-07 workflow и сохраняет JSON/PNG диагностику.

Microsoft Word недоступен в среде. Пиксельное совпадение, естественные метрики AT_LEAST, переносы Word и идентичное число страниц Word не подтверждены. HTML показывает рассчитанный минимум строки; Word может увеличить его по метрикам шрифта/содержимого. Пользовательская калибровка не заменяет проверку сохранённого DOCX.

## Дополнительные блокеры Windows перед выпуском

Фикстура FileShare.None больше не вызывает ConvertTo-Json/Start-Sleep: сигнал готовности публикуется атомарно через .NET, автозагрузка PowerShell-модулей отключена, тайм-аут остаётся 10 секунд. Стадии/PID/время/завершение и проверка снятия блокировки сохраняются в диагностическом Artifact. В реконструкции старого протокола подтверждена загрузка Microsoft.PowerShell.Utility перед ready.json (первый ConvertTo-Json 1637 ms, повторный 65 ms; CLIXML содержит Preparing modules for first use). Превышение 10 секунд из прежнего запуска не воспроизведено, полная причина исторической задержки не доказана.

Windows также выявил необработанный отказ экранной раскладки в повторном обработчике ввода имени врача. Он теперь остаётся видимым предупреждением калибровки, без остановки редактора/автосохранения. Синтетический тест принудительного отказа проверяет доступность настроек, сохранность текста/калибровки и восстановление предпросмотра.

Отдельно воспроизведена слишком длинная цепочка keep-with-next перед подписью: прежний перенос всей цепочки на пустую страницу оставлял ту же невозможную сумму высот и выбрасывал ошибку. Экранная Word-проекция теперь переносит только помещающийся конец цепочки, оставляя предыдущие абзацы на старой странице. Проверяется строгий предел высоты, сохранность каждого символа и подписи. Ветвь экспортного HTML/PDF без Word-проекции не меняет поведение.
