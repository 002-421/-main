# Вставка и локальные редактируемые поля — кандидат на базе 0.4.84

## Аудит 26.11.2026

База — опубликованный тег `xrs-v0.4.84`, коммит
`8a128d5680a262491f43c72b2feeaa3bd092eb2b`. Версия приложения остаётся 0.4.84.
Медицинские тексты, каталоги, идентификаторы исходных полей, экспорт,
профили и механизм обновления не изменяются.

Оба сценария воспроизведены в настоящем Electron до исправления:

* `ExternalPaste` намеренно создавал каждый вставляемый текстовый узел
  только с `textStyle` (шрифт, кегль, местный цвет). Курсив, полужирное и
  подчёркивание позиции вставки отбрасывались даже у обычного текста.
  Поэтому причина не в переопределении курсива HTML-разметкой ChatGPT.
* Обычная жёлтая заливка создаёт `textStyle.backgroundColor`, а не
  служебную разметку. После сохранения документа с контрактом подсветки v1
  она закономерно остаётся ручным оформлением. Не хватало отдельной команды
  создания служебного объекта в рабочем редакторе локальных шаблонов.

## Правило вставки

Исправлен уже существующий режим XRS для внешней вставки (`Ctrl+V`;
`Ctrl+Shift+V` принудительно выбирает этот режим). Внутренняя rich-вставка XRS
с идентификаторами полей остаётся в существующем обработчике; импорт DOCX
не является вставкой из буфера.

Применяются фактические `storedMarks` либо marks позиции курсора/начала
выделения: полужирное, курсив, подчёркивание, зачёркивание, надстрочное и
подстрочное начертание, местные шрифт и кегль. Явный пустой `storedMarks`
считается сбросом начертания. Идентификаторы полей, ссылки и заливка буфера
не копируются как оформление вставляемого текста. Внешние цвета, шрифты и
стили игнорируются так же, как в базовой версии.

Выравнивание, отступы, интервалы новых абзацев берутся отдельно из текущего
абзаца. Пустые строки сохраняются. Соседние абзацы не форматируются.
Одна вставка — одно действие Undo/Redo. После Enter действует фактическое
состояние нового абзаца: сохранённый курсив наследуется; после явного
отключения курсива прежний абзац не служит источником скрытого наследования.

## Команда «Редактируемое поле»

Доступна только в панели «Редактирование шаблона». Выделение обязательно;
допустим текст одного абзаца, без атомарных объектов и жёстких разрывов.
Команда использует существующую модель данных без нового типа marks:

| Выделение | Существующий механизм |
|---|---|
| Весь текст абзаца | `editableHighlight` + `templateHighlight`; размеры `0,0` получают независимые `templateSize` |
| Отдельный размер `0,0` (также `0,00`) | `templateSize`, стандартная замена всего заполнителя первой цифрой |
| Обычный текстовый фрагмент | `templateField` с уникальным локальным ID `local.editable.*`, `hint`, `original`, `filled` |

Абзацную подсветку не подменяем полем пациента. Для текстового фрагмента
используется уже существующее общее текстовое поле; автоматическая
подстановка Ф.И.О., номера, врача и дат распознаёт прежние служебные ID.
Их переназначение новой командой запрещено. Соседние объекты не объединяются.
Повторное назначение допустимо только при точном выделении всего локального
поля. Исходные ID размеров сохраняются.

Частичный фрагмент, пересекающий размер, отклоняется с объяснением:
нужно выделить весь абзац либо размер отдельно. Это предотвращает наложение
двух владельцев заполнения. Текстовое поле ограничено 2000 символами.

При явном назначении служебного поля ручная жёлтая заливка снимается только
с выделенного текста и заменяется служебной подсветкой того же цвета.
Никакого распознавания полей по цвету при открытии нет. Обычная заливка,
назначенная кнопкой цвета без команды поля, остаётся обычной заливкой.

Существующие правила завершения сохраняются:

* Изменение текста абзаца снимает его общую служебную подсветку; ожидающие
  размеры и самостоятельные текстовые поля сохраняются.
* Изменение части текстового поля завершает только это поле; полная замена
  или удаление не затрагивает соседние поля.
* Ввод/вставка в незаполненный размер заменяет весь его заполнитель.
* Вставка внутрь локального текстового поля сохраняет его ID и местное
  начертание, завершает только это поле. Многострочное значение внутри
  поля хранится как текст с переводами строк, как у существующих полей;
  обычная многоабзацная вставка вне поля создаёт отдельные абзацы.
* Выделение и форматирование сами по себе поля не заполняют.
* Создание и заполнение участвуют в обычном Undo/Redo.

Локальные поля проходят прежний JSON-валидатор и собственный DOCX-контракт.
Для новых нетронутых текстовых полей сохранены отдельные стилизованные runs
при создании нового протокола: сброс к hint не должен сплющивать их оформление.
Алгоритм сброса исходных служебных полей не меняется.

## Проверка

`tests/paste-fields.test.mjs` проверяет marks, абзацы, Undo/Redo,
независимость объектов, ограничения назначения, стилизованные значения по
умолчанию, 40 исходных ID восьми Spine и неизменность границ AI Review.

`tests/paste-fields-electron.mjs` использует настоящий буфер Electron,
кнопку редактора, отдельный синтетический профиль, сохранение и холодный
перезапуск, собственный DOCX round trip и реальный PDF. Диагностика и
матрица — `test-output/paste-fields/`. Медицинские формулировки в исходных
каталогах не редактируются; тестовые вставки существуют только во временном
профиле. Проверки полного каталога, Spine, шрифтов, истории и экспорта
дополнительно выполняются существующими наборами.

Проверка в установленном Microsoft Word и на рабочем компьютере владельца
не подменяется проверкой OOXML/Chromium. Эти действия требуют ручной приёмки.

## Ручная приёмка

1. Открыть копию тестового протокола, включить курсив и вставить несколько
   абзацев из ChatGPT/Word. Проверить курсив, отступы, Ctrl+Z/Ctrl+Y.
2. Открыть ПОП → «Редактировать шаблон». Выделить обычный текст и нажать
   «Редактируемое поле». Отдельно назначить два размера `0,0`.
3. Рядом применить обычную жёлтую заливку кнопкой оформления.
4. Сохранить локальную версию, открыть новый протокол из неё. Заполнить
   первое поле и первый размер: их подсветка должна исчезнуть, соседние
   незаполненные поля должны остаться жёлтыми, ручная заливка — сохраниться.
5. Перезапустить XRS, повторить в локальной версии; проверить шапку, врача,
   дату, Undo/Redo, сохранение/открытие, DOCX и PDF.
6. Сравнить исходный шаблон и ранее сохранённый протокол: изменения локальной
   версии не должны их переписывать. Для отмены кандидата использовать
   опубликованную 0.4.84; созданные тестовые локальные версии восстанавливать
   штатными резервными копиями шаблонов.

Кандидат не является новым релизом. Merge, повышение версии и публикация
не выполняются в рамках задания.
