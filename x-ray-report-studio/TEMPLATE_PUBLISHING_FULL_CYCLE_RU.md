# XRS 0.4.87 — простая загрузка общего каталога

Актуальная модель владельца: HTTPS и SHA-256 без Root, Ed25519, USB,
Actions dispatch, PR или Environment approval при публикации.
Это изменение относится только к шаблонам. Updater EXE сохранён.

## Работа администратора

На каждом административном Windows-компьютере один раз подключите GitHub через
кнопку «Подключить GitHub» в XRS. Программа откроет системный браузер и покажет
код официального GitHub Device Flow. Подключите учётную запись 002-421.
GitHub CLI, Git и отдельная установка Node.js не требуются. Авторизация хранится
в профиле Windows в зашифрованном виде через Electron safeStorage / DPAPI;
в renderer передаются только состояние подключения и код подтверждения.
Обычным врачам авторизация GitHub не нужна.

Для производственного подключения требуется публичный Client ID OAuth App с
включённым Device Flow. Пока он не задан в github-oauth-config.cjs, подключение
отклоняется понятным сообщением; реальная авторизация ещё не подтверждена.

В настройках в разделе медицинских шаблонов и в административном редакторе
есть одна и та же команда «Загрузить шаблоны». Она запрашивает PIN 4–6 цифр.
Каждый вызов публикации отдельно проверяет PIN в main process; сессия редактора
не является разрешением отправки. PIN хранится как scrypt-хеш, попытки ограничены.
Старый длинный PIN можно заменить после входа в существующий административный
редактор. PIN не даёт права GitHub без авторизации доверенного компьютера.

Публикуется встроенный утверждённый каталог плюс явно сохранённые утверждённые
общие редакции. Чтобы изменить стандарт: сохраните и проверьте Draft в существующем
редакторе, затем нажмите «Сохранить в утверждённый общий каталог». Личные редакции,
неутверждённые Draft и открытый пациентский протокол не включаются автоматически.

После нажатия «Загрузить шаблоны» программа готовит полный каталог из 113 исходных
шаблонов с утверждёнными изменениями. Никакие JSON, ключи или GitHub Actions
пользователь вручную не редактирует. Повторный вход нужен только при отзыве/истечении
GitHub-авторизации. При отсутствии изменений новая версия не создаётся.

## Упаковка и публикация

SchemaVersion 3: catalog-manifest.json + catalog.xrszip (один catalog.json).
ZIP содержит только структурированные данные, без скриптов. Размеры, пути,
схема, версии, SHA-256 и служебные поля проверяются до установки.
GitHub Releases xrs-templates-vN.N.N неизменяемы. Аннотированный тег резервирует
версию и связывает её с UUID и SHA запроса. Сначала загружается закрытый draft
Release, проверяются его assets, затем открывается Release и обновляется latest.
Успех показывается только после повторной публичной загрузки и проверки SHA.

Новая операция не создаёт PR и не изменяет main. Используется обычное право
владельца создавать Releases; существующие Environments и защита main не меняются.
При сетевой неопределённости локальный журнал сохраняет запрос; следующий запуск
продолжает ту же операцию и проверяет уже опубликованную версию без clobber.

SHA-256 не защищает при одновременной подмене архива и манифеста вследствие
компрометации самого GitHub-источника. Владелец принял эту модель доверия.
Приватные signing keys, PAT и пароли в приложении отсутствуют.

## Работа врача

Настройки → версия пакета шаблонов → Обновить → список изменений → Установить.
Используется прежний TemplateCatalogStore с адаптером нового формата, резервные поколения, история и откат. Данные нового формата хранятся в template-catalog-v2; старые кэши v1 сохраняются отдельно и не интерпретируются как неподписанные.
ZIP каждой версии скачивается один раз. Локальный кэш хранит отдельные JSON-шаблоны по хешу содержимого, поэтому неизменённые документы переиспользуются, а история не дублирует весь каталог при каждой правке.
Версии приложения и каталога независимы. Открытые и сохранённые протоколы не меняются.
Base/Local/Incoming сохраняет личные редакции и обе стороны конфликта; сравнение
показывает форматирование. Офлайн используется прежний рабочий каталог.

Старые криптографические функции оставлены только для тестируемой совместимости
библиотеки. Новый источник и штатная публикация их не используют. Старый мастер
генерации ключей выведен из обычного запуска.

## Официальный выпуск

Отдельные пользовательские RC и ручные установки из Artifacts не используются.
Разработка и Windows Electron проверки выполняются в CI. После успешной проверки
и отдельного разрешения владельца используется штатный Stable workflow.
Пользователь обновляет действующую Stable штатной кнопкой XRS; проверка публикации
каталога входит в общую проверку установленного официального релиза.
Синтетический GitHub mock в CI не считается реальной публикацией.
