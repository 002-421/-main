# Тестовый комплект XRS-05 для Windows 11

Комплект предназначен только для проверки интеграционной ветки. В нём находятся переносимая копия приложения и синтетическое обновление на следующий patch-номер. Манифест и ZIP обновления лежат локально внутри комплекта. Публичный канал обновлений не используется и не меняется.

## Изоляция

Распакуйте `XRS-05-Windows-Test-Kit.zip` в отдельную папку, например:

`%USERPROFILE%\Desktop\XRS05 Тестовая сборка`

Запускайте приложение только через `Run-Test-App.cmd`. Тестовый маркер включает отдельные каталоги:

- приложение: `App_<версия>` рядом с комплектом; обновление создаёт соседний `App_<версия>`;
- профиль Chromium/Electron и открытые тестовые документы: `XRS-Test-Data\Profile`;
- настройки appData: `XRS-Test-Data\AppData`;
- печати, словарь и ярлык: только внутри `XRS-Test-Data`;
- резервные копии: `XRS-Test-Data\AppData\X-ray Report Studio Backups`.

Приложение из тестового комплекта не меняет рабочий ярлык на Рабочем столе. Не запускайте `Install.cmd` из других пакетов и не переносите тестовый профиль в рабочую установку.

Используйте только искусственные сведения: например, «Тестовый Пациент А», «Тестовый Пациент Б», произвольные даты и текст `СИНТЕТИЧЕСКИЙ ПРОТОКОЛ`. Не вводите реальные медицинские данные.

## Сценарий проверки

1. Распакуйте комплект в путь с пробелами и кириллицей и запустите `Run-Test-App.cmd`.
2. Создайте три протокола с разными синтетическими именами и шаблонами. В каждом измените текст, сохраните рабочие черновики штатным способом и закройте приложение.
3. Запустите комплект повторно. Убедитесь, что открылись те же вкладки, активный документ и содержимое.
4. Откройте настройки, проверьте синтетическое обновление и нажмите «Установить обновление». Подтвердите обновление. Тестовый манифест и ZIP читаются только из папки `Updates` комплекта.
5. После переключения проверьте версию в настройках, содержимое документов и наличие резервной копии в указанной выше папке. В `manifest.json` резервной копии проверьте количество файлов и SHA-256; тексты не нужно отправлять или публиковать.
6. В настройках выберите «Вернуться к предыдущей рабочей версии». Сверьте показанные версии, подтвердите откат и проверьте, что запустилась исходная копия, документы остались на месте, а текущая версия также получила отдельную резервную копию.
7. Для проверки отказа до резервирования закройте приложение, временно переименуйте файл `Updates\XRS_Test_Update_<версия>.zip`, снова проверьте обновление и попытайтесь установить его. Установка должна завершиться ошибкой, исходная версия и ярлык в `XRS-Test-Data\Shortcuts` должны остаться рабочими. Верните имя ZIP после проверки.
8. Закройте окно приложения. Для удаления тестовой установки удалите только распакованную папку `XRS-05-Windows-Test-Kit`, включая соседние `App_*` и `XRS-Test-Data`. Рабочая папка и рабочий ярлык `X-ray Report Studio` не затрагиваются.

## Автоматические сценарии и ограничения

Windows CI проверяет сборку, разбор PowerShell-скрипта установщика, реальную запись и атомарную замену `.lnk` через Windows Script Host, side-by-side распаковку synthetic ZIP в каталоге с кириллицей и пробелами, хешированную резервную копию искусственного профиля, совместимость/отказ отката, запуск Electron редактора, Undo/Redo и восстановление рабочего пространства.

CI не запускает официальный установщик, не меняет пользовательский Рабочий стол и не использует рабочий профиль. Ошибка первого запуска проверяется автоматическими тестами обработчика на контролируемом синтетическом процессе; ручной сценарий намеренно не просит повреждать Windows-установку. GUI-откат и путь локального обновления нужно пройти вручную по шагам выше на Windows 11.

Резервная копия создаётся после сохранения локальных черновиков и `flushStorageData()`, при заблокированном редакторе. Это не является атомарным снимком всего Chromium LevelDB при внешнем процессе, одновременно меняющем профиль. Перед проверкой закройте все экземпляры тестовой сборки; для рабочей версии ручные проверки не выполняйте.
