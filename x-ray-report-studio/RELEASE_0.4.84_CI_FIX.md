# XRS 0.4.84: устранение блокировки при проверке обновления

Сбой 45651860483 вызван тестовой фикстурой, а не нарушением SHA-256 в приложении.
Опубликованная 0.4.83 в изолированном test kit принимает только имя
`XRS_Test_Update_M.m.p.zip`. Фикстура передавала `candidate.zip`; валидатор
отклонял его до скачивания и вычисления SHA. Публичный код ошибки для обычного
Error — UPDATE_FAILED, фаза manifest. Текст исходного исключения опубликованного
валидатора: «Недопустимый файл локального тестового обновления».

Причина воспроизведена непосредственно модулем update-channel.cjs из Setup ZIP
0.4.83, проверенного по SHA-256 a1d0bad8830b0e700b3d53c5fa29b1b0fdecc9f86902890a419453daf3d1b0f1.
Его байты совпадают с текущим производственным валидатором. Производственные
URL-проверки, SHA-256, ZIP-защита, updater и исполняемый код XRS не менялись.

Фикстура использует `XRS_Test_Update_0.4.84.zip` через существующий изолированный
file: transport. Unit-тест дополнительно проверяет, что такой URL не разрешён
в обычном рабочем канале, а traversal и произвольные имена остаются запрещены.

Windows acceptance сначала воспроизводит прежний отказ и читает внутренние
update-*.log: ожидаются UPDATE_FAILED/manifest и отсутствие checksum-check.
Затем проверяется корректность нового манифеста, неверная SHA, внутренние
expected/actual, ошибка checksum и отсутствие staging/extraction. Успех проверяет
точный ZIP, checksum-verified, live-renderer-update-complete, сохранность протокола
и настроек, ярлык, холодный запуск, stable install-state, прежний EXE и побайтовое
совпадение установленных модулей с ZIP. Настоящий SHA-test не заменён проверкой
общего сообщения UPDATE_FAILED.

В test-output/release-084/update-events.json сохраняются только разрешённые
события, фазы, коды, операции, версии, размеры и SHA. Пути, сообщения, тексты
протоколов, личности и credentials не копируются. При ошибке CI annotation
содержит стадию теста и последний зарегистрированный внутренний код/фазу.

Это описание исправления и критериев. Успех нового Windows CI, фактическая
публикация и хеш публичного ZIP указываются в финальном отчёте после проверки.
