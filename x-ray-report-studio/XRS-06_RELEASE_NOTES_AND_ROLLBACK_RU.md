# XRS-06 — заметки кандидата 0.4.54 и план отката

## Что входит в кандидат

- Вкладки показывают полную фамилию. Если у одного пациента открыто несколько исследований, рядом выводится трёхбуквенный код исходного шаблона. Полное название исследования остаётся в заголовке редактора и подсказке вкладки. Длинные вкладки сохраняют ширину текста; весь ряд прокручивается горизонтально.
- Undo/Redo используют отдельную историю обратимых ProseMirror-операций для каждого протокола. История включает позиции курсора до и после действия и сохраняется в отдельном ключе локального Chromium-хранилища.
- Глубина истории настраивается значениями 100, 250, 500 или 1000; по умолчанию — 500. История ограничена объёмом 512 КиБ на протокол. Повреждение или несовместимость истории очищает только историю; сохранённый текст протокола не удаляется.
- Данные истории остаются необязательными и отделены от формата документов. При изменении документа старой версией fingerprint не совпадёт, поэтому устаревшая история будет отброшена при следующем запуске новой версии.
- XRS-04 сохраняет подтверждение пользователя перед установкой, локальную проверку SHA-256, резервную копию профиля, установку рядом с предыдущей версией, smoke-check первого запуска и ручной откат. Ни один резервный архив автоматически не удаляется.

## План безопасной проверки и отката

1. Проверять только изолированный Windows test kit из артефакта CI, запущенный через `Run-Test-App.cmd`. Профиль, приложения, резервные копии и ярлыки должны находиться внутри папки комплекта; рабочую установку 0.4.53 не запускать и не менять.
2. Ввести искусственные данные, проверить локальное сохранение и Undo/Redo после переключения вкладок и полного перезапуска. До обновления экспортировать тестовый документ, если он нужен для сравнения.
3. Запустить локальное синтетическое обновление 0.4.54 → 0.4.55. Сначала выбрать «Позже» и проверить, что версия не изменилась; затем подтвердить установку. Убедиться, что SHA-256 проверен, новая версия стартовала, а старый каталог версии и профиль остались доступны.
4. Проверить отдельную локальную резервную копию и её чтение. При ошибке резервирования установка должна отмениться, а прежняя версия и ярлык должны остаться рабочими.
5. Выполнить ручной откат 0.4.55 → 0.4.54 только через настройку приложения. Проверить отображённые номера версий, создать отдельную резервную копию текущего состояния и подтвердить откат. При сомнении в совместимости не запускать старую версию на изменённых данных; восстановить синтетический профиль из проверенной копии в отдельный каталог.
6. Оставить оба каталога приложений и все резервные копии до завершения ручной проверки. Удалять можно только всю папку test kit после закрытия всех его процессов; это не затрагивает 0.4.53.

Кандидат не меняет публичный `downloads/latest.json`, автообновление, официальные ZIP или GitHub Release. Обновление пользователям и откат рабочей установки не выполняются автоматически.
