# Local AI review

The first model is Qwen3 8B Q4_K_M. The application does not put its multi-gigabyte weights in the installer or repository. On first use, Electron downloads the fixed GGUF file over HTTPS and stores it under `%LOCALAPPDATA%/MRI Report Studio/ai-models/` on Windows. This path is independent of the source checkout, app version, and installer folder, so editing code and rebuilding does not download the model again. An interrupted transfer resumes from its `.part` file. A completed file is recorded with its model ID, size, and SHA-256 digest.

The renderer reaches model services only through the Electron preload/API boundary. Keep the review UI independent of model paths and runtime details. The next provider can use the same review contract for either this local model or a trusted MRI Report Studio server on the clinic LAN. In LAN mode, the server owns one model copy; clients send only the report text needed for review. The server should bind to the clinic network interface intentionally, require authentication, use TLS, and avoid retaining report text or model prompts in logs.

Review output should be structured findings tied to exact report passages: category, severity, quoted text, explanation, proposed wording, and confidence. The app validates each quote against the document and highlights it for physician review. It never applies model edits automatically. Numbers, units, laterality, negation, dates, and clinical conclusions are treated as protected content; possible medical contradictions are suggestions to verify, not diagnosis.
