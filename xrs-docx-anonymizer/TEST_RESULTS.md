Дата: 17.11.2026 (Asia/Novosibirsk). Использовались только синтетические документы.

## Linux / исходный код

- Python 3.12.14, lxml 6.1.1, python-docx 1.2.0, Pillow 13.0.0.
- `python tools/run_tests.py <report.json>`: **39 тестов, OK, 6,451 с**. Это тот же unittest-набор с автоматическим сохранением свидетельства сборки.
- Включён пакет из **1000 DOCX** и повторная обработка в ту же папку без перезаписи первого результата.
- Проверены Ф.И.О. врача и пациента, заглавные имена, инициалы, подписи, даты рождения/исследования, номера, email/телефоны/адреса/идентификаторы и сведения в таблицах.
- Проверены реальные PNG/JPEG в тексте, таблице, header/footer; также удаление медиа с расширениями TIFF/BMP/GIF/EMF/WMF/SVG, orphan media, OLE, внешних связей, свойств и customXml.
- Проверены комментарии, удаления/вставки/moveFrom в Track Changes, поля, скрытый текст, наследуемые стили скрытия, явное выключение скрытия и скрытие в docDefaults.
- Проверены сноски, текстовые блоки VML, границы runs/переносов строк, стиль и нумерация, повторное открытие результатов через python-docx.
- Измерения `12 × 8 × 4,5 мм`, `ADC 0,9 × 10⁻³ мм²/с`, `L4-L5`, `T1/T2`, стороны и медицинские эпонимы сохраняются в соответствующих тестах.
- Проверены повреждение ZIP/XML, ZIP bomb, path traversal, дубликаты, лимит записей, DTD/XXE в UTF-8 и UTF-16, неизвестный контейнер, неверная вложенность, небезопасная ссылка на header и остаточный идентификатор во втором проходе.
- Проверены изоляция REVIEW, отсутствие DOCX для BLOCKED, блокировка параллельного запуска, отмена, отсутствие исходных значений/путей в отчётах и неизменность оригинала.
- Полный синтетический запуск под запретом socket.connect/create_connection/getaddrinfo прошёл без сетевых/DNS вызовов.
- Подтверждено наличие бинарных Windows x64 wheels для закреплённых основных зависимостей.

## GUI

Окно проверено на Linux с системным Python/Tk 8.6. Выполнен запуск из GUI на четырёх синтетических DOCX: ожидаемые 2 PASS, 1 REVIEW и 1 BLOCKED; интерфейс показал завершение, папки и отчёты проверены отдельно. Встроенная в среду разработки сборка Python с Tk 9.0 некорректно отображает кириллицу; системный Tk 8.6 отображает интерфейс правильно. Windows-сборка использует официальный Python 3.12 и Tk 8.6. Linux-проверка не заменяет проверку Windows GUI.

## Windows

Первая [Windows-сборка](https://github.com/002-421/-main/actions/runs/44104660780) успешно завершена: Windows Server 2022 x64, Python 3.12.10, 36 тестов, GUI/CLI EXE, frozen CLI synthetic smoke, запуск GUI, лицензии и ZIP с SHA256. После неё добавлены регрессии: полное имя с фамилией-эпонимом, точное удаление номера протокола и запрет сетевых папок; текущий набор содержит 39 тестов. [Вторая Windows-сборка](https://github.com/002-421/-main/actions/runs/44105385056) также прошла успешно: 38 тестов, frozen CLI и проверка наличия окна GUI с ожидаемым заголовком.

В последующих дистрибутивах BUILD_EVIDENCE.json автоматически фиксирует платформу, SHA коммита и число пройденных тестов этой сборки. Результат окончательной сборки также сообщается в итоговом ответе. Artifacts хранятся 14 дней; исходники и workflow остаются в отдельной ветке.

Windows 11 x64 / Microsoft Word и инструментальное наблюдение сетевой активности frozen EXE требуют приёмочной проверки. Открытие через python-docx не является подтверждением отрисовки Word или полной XSD-валидацией.
