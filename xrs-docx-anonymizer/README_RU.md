# XRS DOCX Anonymizer 0.1.0

Отдельная локальная утилита для подготовки медицинских DOCX. Интерфейс на русском языке; X-ray Report Studio не требуется. Оригиналы открываются только для чтения. Интернет, облачные модели и телеметрия в приложении отсутствуют.

**Статус: READY FOR TEST — MVP для приёмочных испытаний.** Windows EXE собран в GitHub Actions; синтетические тесты и проверка frozen CLI пройдены на Windows Server 2022 x64. Проверка на целевой Windows 11 x64 / Microsoft Word ещё требуется. Подтверждённые проверки перечислены в TEST_RESULTS.md; BUILD_EVIDENCE.json в дистрибутиве содержит результат тестов именно этой сборки.

## Запуск переносимой Windows-сборки

1. Распакуйте весь `XRS-DOCX-Anonymizer-Windows-x64.zip` в отдельную локальную папку.
2. Запустите `XRS-DOCX-Anonymizer.exe`. Папка `_internal` должна оставаться рядом.
3. Выберите локальную папку с DOCX и отдельную локальную папку результата. Они не должны быть вложены друг в друга. UNC-пути и подключённые сетевые диски Windows не поддерживаются.
4. Нажмите «Начать обезличивание». Все четыре защитные опции обязательны; отключить их нельзя.
5. Изучите `Reports/summary.csv`, `Reports/summary.json` и папку `Review`.

Python, Word и интернет для запуска собранного приложения не нужны. Не требуется установка в XRS или права администратора. Word нужен только для самостоятельной проверки отображения результата.

## Выходные данные

```text
Результат/
  Anonymized/CASE-000001.docx  # только PASS
  Review/CASE-000002.docx     # только REVIEW; может содержать оставшиеся ПДн
  Reports/summary.csv
  Reports/summary.json
  Reports/run-000001.json     # история отдельных запусков
  .reservations/CASE-000001.reserved
```

BLOCKED не создаёт выходной DOCX. Код резервируется и при ошибке, чтобы не использовать его повторно. Исходные имена, пути и структура подпапок в отчёт не записываются. Скрытая `.reservations` содержит только пустые файлы с CASE-ID. Не удаляйте её при продолжении обработки. Нумерация учитывает существующие результаты и продолжается при следующем запуске.

`summary.*` содержит последний запуск; `run-*.json` сохраняет историю. История текущего запуска обновляется после каждого документа. Файл `.xrs-anonymizer.lock` исключает два одновременных запуска в одну папку; после аварии удалить его можно только убедившись, что приложение закрыто.

## Статусы

| Статус | Значение | Где находится DOCX |
| --- | --- | --- |
| PASS | Пройдены реализованные автоматические проверки. Перед внешней передачей требуется ручной контроль. | Anonymized |
| REVIEW | Найдены неоднозначные имена, даты, идентификаторы или изменения сложной структуры. | Review |
| BLOCKED | Неизвестный компонент, повреждение, превышение лимитов, ошибка очистки/проверки/записи. | Не создаётся |

`removed_fields` — число объединённых замен правил, а не число людей. `removed_images` — максимум количества медиафайлов и отношений типа image; это число ресурсов/отношений, не число визуальных размещений. Категории и причины в отчёте представлены фиксированными кодами без исходных значений.

## Из исходников

Для разработки нужен Python 3.12 x64 с Tkinter. Единственная библиотека приложения — lxml 6.1.1. python-docx и Pillow применяются для синтетических тестов; PyInstaller — для Windows-сборки.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m xrs_anonymizer
```

CLI из исходников:

```powershell
python -m xrs_anonymizer --source "D:\LocalInput" --output "D:\LocalOutput"
```

CLI из дистрибутива:

```powershell
.\XRS-DOCX-Anonymizer-CLI.exe --source "D:\LocalInput" --output "D:\LocalOutput"
```

По умолчанию включены подпапки; `--no-recursive` отключает обход подпапок. CLI выводит только счётчики. Код завершения 2 означает BLOCKED или ошибку запуска; REVIEW отражается в отчёте, но не вызывает код 2. «Остановить» завершает текущий документ и сохраняет накопленный отчёт.

## Синтетические тесты

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -t . -v
python tools/generate_synthetic.py synthetic-suite --bulk 1000
```

Генератор не принимает исходные медицинские файлы. Весь набор вымышленный. Тесты временно создают свои DOCX вне репозитория и удаляют их после выполнения.

## Сборка Windows

На Windows x64 с Python 3.12 запустите `./build-windows.ps1` из PowerShell. Скрипт проверяет тесты, собирает переносимую папку GUI и дополнительный CLI EXE, включает лицензии, проверяет frozen CLI на синтетическом документе и проверяет запуск GUI. Результат: `dist/XRS-DOCX-Anonymizer-Windows-x64.zip`.

В `.github/workflows/windows-build.yml` подготовлена сборка Windows на отдельной ветке, без публикации релиза и без слияния в Stable. GitHub Actions использует интернет для загрузки инструментов сборки. В workflow поступает только исходный код и синтетические тесты. Сборка и обычная работа приложения — разные процессы: установленная утилита не обращается к сети.

В общем репозитории workflow находится в `.github/workflows/xrs-docx-anonymizer-windows.yml`, а исходники — в отдельной папке `xrs-docx-anonymizer`. [Сборки отдельной ветки](https://github.com/002-421/-main/actions/workflows/xrs-docx-anonymizer-windows.yml?query=branch%3Acodex%2Fxrs-docx-anonymizer). Откройте успешный запуск и скачайте artifact `XRS-DOCX-Anonymizer-Windows-x64`; затем распакуйте лежащий внутри Windows ZIP. Для скачивания artifact GitHub может требовать вход в учётную запись.

Для сборки в изолированном контуре заранее подготовьте на Windows с теми же Python и архитектурой папку wheelhouse:

```powershell
python -m pip download --only-binary=:all: -r requirements-dev.txt -d wheelhouse
./build-windows.ps1 -Offline
```

Перенесите исходники, Python и wheelhouse в разрешённый локальный контур. На компьютере конечного пользователя wheelhouse и Python не нужны.

## Ограничения

- Правила не являются полноценной NER-моделью. Опечатки, редкие, иностранные и одиночные имена, сведения без подписи, разбивка между разными абзацами и косвенные идентификаторы могут остаться. PASS не гарантирует анонимность.
- Удаляются подписи врача, все изображения и вложения. Их медицинское содержимое не распознаётся и не переносится.
- Сохраняются текст, простые стили, выделения, абзацы, таблицы, нумерация и поддержанные колонтитулы/сноски. Шрифты и тема нормализуются. Макет, сложные поля, диаграммы, математические объекты и расширения Word могут измениться или вызвать REVIEW/BLOCKED.
- Track Changes принимаются: вставки остаются и проходят очистку, удаления и moveFrom полностью исключаются. Истории версий в результате нет.
- Текстовые блоки внутри фигур переносятся в обычный текст и всегда дают REVIEW.
- Даты рождения и исследования с подписями удаляются. Даты без подписи дают REVIEW, чтобы не терять медицинскую хронологию автоматически.
- Значения после идентифицирующих подписей удаляются до конца строки/поля. Если в той же строке без разделителя записано клиническое описание, оно также может быть удалено; это нужно проверять вручную.
- REVIEW хранится в отдельной папке без шифрования средствами приложения. Защищайте её правами Windows и шифрованием диска. Не передавайте её как обезличенный архив.
- Нет открытой таблицы соответствий CASE-ID и исходных имён. При необходимости повторной связи с оригиналом заранее организуйте отдельный защищённый локальный процесс.
- Проверка OOXML не является полной валидацией по XSD Microsoft и не подтверждает идентичную отрисовку в Word. Конечный контроль — в Windows 11 и Word.
