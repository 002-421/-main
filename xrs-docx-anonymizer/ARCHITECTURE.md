# Архитектура

Python 3.12 + Tkinter + lxml. MVP работает отдельно от XRS. Нет сервера, базы данных, фонового сервиса или сетевых зависимостей времени выполнения.

## Поток обработки

1. `batch.discover` перечисляет DOCX, исключая ссылки, временные файлы Word и недопустимое пересечение папок.
2. `Session` берёт локальную блокировку и резервирует безопасный CASE-ID без имени источника.
3. `read_package` читает ZIP с лимитами числа записей, размера, распаковки и отношения сжатия. Архив не извлекается на диск.
4. XML разбирается lxml без DTD, разрешения сущностей, загрузки внешних ресурсов, recovery и huge_tree.
5. `Rebuilder` создаёт новый пакет по разрешённому набору частей, XML-элементов и атрибутов. Метаданные, media, OLE, ActiveX, пользовательский XML и исходные relationships не копируются.
6. Изменения принимаются, удалённые фрагменты и скрытый текст исключаются. Прямое скрытие и наследование скрывающих стилей поддержаны.
7. Имена стилей, номера сносок, имена частей и отношения заменяются новыми техническими идентификаторами. Свободные строки в атрибутах оформления не копируются.
8. Сначала обрабатываются точные служебные поля «Дата», «Дата исследования», «Дата проведения», «Дата выполнения» и «Дата обследования». Метка и дата удаляются вместе, даже если Word разбил значение между runs. Дата рождения проходит существующее правило персональных полей.
9. Даты из клинического контекста и даты без ясной служебной подписи сохраняются и вызывают REVIEW. Медицинские измерения, уровни, углы и другие числа не удаляются глобальным поиском похожих на даты последовательностей.
10. Строка «Область и вид исследования» сохраняется без нормализации. Исходный текст поля сверяется с выходным документом в `verify`; изменение блокирует результат. Дата в таблице с отдельной ячейкой метки удаляется вместе с соответствующей ячейкой значения.
11. Остальные текстовые правила работают по целому абзацу, включая границы runs и переносы строк. Неизменённый текст остаётся в исходных runs со стилями.
12. `verify` независимо проверяет разрешённые части/элементы/атрибуты, вложенность основных элементов, relationships, остаточные служебные даты и сохранение поля вида исследования. Затем ZIP создаётся заново с фиксированными временными метками и без исходных ZIP-комментариев; проводится CRC и повторная проверка распакованных байтов результата.
13. Только проверенные байты записываются через exclusive create. PASS → Anonymized, REVIEW → Review, BLOCKED → только отчёт. Все ошибки наружу переводятся в фиксированные безопасные коды.

GUI работает в главном потоке Tk; последовательный worker обрабатывает по одному документу. Очередь передаёт только счётчики и фиксированные сообщения. Память освобождается между документами; для тысячи документов не загружается тысяча DOCX одновременно. Отмена действует между документами.

## Почему не только python-docx

python-docx сохраняет произвольные части исходного OOXML-пакета. Это полезно для редактирования, но непригодно как единственная гарантия очистки. Здесь он используется только для создания синтетических образцов и проверки открытия результатов; низкоуровневая очистка не зависит от python-docx.

## Политика неизвестных компонентов

- Известные опасные или идентифицирующие компоненты целиком отбрасываются и не включаются в пакет.
- Неизвестная часть пакета → BLOCKED.
- Неизвестный текстовый контейнер Word → BLOCKED.
- Неподдержанное свойство оформления → REVIEW.
- Неподдержанное расширение с текстом, перенос текста из фигуры, altChunk/control/subDoc → REVIEW после удаления объекта.
- Неразрешимая ссылка на колонтитул/сноску/нумерацию, небезопасный ZIP/XML и нарушение постусловий → BLOCKED.

Поддержка DOCX Transitional. Strict OOXML, зашифрованные документы, DOC/DOCM, PDF и DICOM не поддержаны. Неизвестные форматы не преобразуются через Word/LibreOffice, макросы и объекты не выполняются.
